# Explicit identifier token policy

This policy applies only to explicit student identifiers in outbound names, titles, directions and decoded assignment fields. The existing final-payload guards remain responsible for every sharing/export action. It does not establish that arbitrary text is free of personal information.

1. Normalize text to NFC. Recognize case-insensitive ASCII `ID` or `SID`, optionally prefixed by `student`, or `student` followed by `number`, `no.`, `no` or `#`. Whitespace, underscores and hyphens may separate `student` from its marker.
2. Marker scanning never consumes the preceding boundary, so rejecting `student no.` cannot hide a following `ID` in `student no.ID1234`. A marker begins at the start of text or after a character outside Unicode letters, combining marks, numbers and connector punctuation. Thus `αID 1234`, `identity1234`, `sideline1234` and `_ID1234` are not markers embedded in ordinary words/codes.
3. A compact word marker may end directly before a decimal digit or punctuation, but not inside a longer letter/mark word. `student number1234` blocks; `student numberline4`, `student notation4`, `student notebook4` and `student no.tation4` do not. A `#` marker itself supplies a separator, so `student#A1234` is explicit. `ID`/`SID` may also carry the existing `number`/`no.` qualifier, including compact numeric forms.
4. Skip the punctuation/whitespace separators after a recognized marker/qualifier. Examine only the immediate non-whitespace value token. If it contains any Unicode decimal digit (`Nd`), block it. The token has no suffix allowlist or trailing JavaScript word boundary: underscores, hyphens, periods, slashes, commas, quotes, parentheses and adjacent Unicode letters cannot exempt the marked value. Do not scan later whitespace-separated words: `ID class 4` is not an immediate identifier value.
5. Preserve the existing independent SSN/long-number checks and name/email/phone advisories. Unmarked codes such as `Class 1234_ABC`, `Class α1234`, `A1234_B` and `4B-SPRING` remain allowed under the existing rules. Phone masking does not exempt a separate explicit identifier.

The same implementation and [matrix fixture](../tests/fixtures/explicit-identifier-policy.json) are maintained in Count It, Mallet Map and Pulse Pocket. The fixture includes explicit allow/block/warn controls, marker × value × suffix combinations, Unicode left-boundary controls, compact forms, phone combinations and ordinary-word false positives. Boundary tests additionally exercise decoded duplicate queries or nested name payloads and real output actions with synthetic destinations.

Compatibility: the marker scanner uses `RegExp.exec`, lookahead and ES2018 Unicode property escapes; it adds no lookbehind, match indices, `v` flag or new API. [WebKit implemented property escapes in 2017](https://webkit.org/blog/8001/release-notes-for-safari-technology-preview-42/); [MDN's compatibility data](https://github.com/mdn/browser-compat-data/blob/main/javascript/regular_expressions.json) records Safari 11.1 support. This is syntax/contract evidence for Pulse's existing iOS 15 target, not physical iOS 15 or screen-reader acceptance. No collection, storage, network destinations, permissions or dependencies are added.
