# Local PNG copy and fallback

Count It already rendered a local result-summary PNG for download. Copy result image now uses that same renderer, while Download PNG remains explicit. The helper detects secure context, clipboard.write, ClipboardItem and optional image/png support. It invokes write directly from the click with a PNG promise, before waiting on canvas encoding, to retain user activation. Unsupported APIs, denied writes and encoding failure announce a download or text-summary fallback. No permission request is made on load, no clipboard is read, and no image is uploaded.

Only the existing result-summary fields enter the image. Its footer and the result card describe a browser-generated record, not proof of authentic work. The existing unkeyed verification checksum, assignment fields, attempts, seeds, scoring and storage remain unchanged; no server-verified mode or tracking is introduced.

Compatibility basis: [W3C Clipboard API](https://www.w3.org/TR/clipboard-apis/) defines secure-context ClipboardItem PNG promises; [WebKit's implementation guidance](https://webkit.org/blog/10855/async-clipboard-api/) requires writes within a user gesture; [Google's Async Clipboard guidance](https://web.dev/articles/async-clipboard) covers PNG and permission differences. Target-app image pasting and actual OS clipboard writes vary by browser; feature detection/fallback is authoritative. No desktop paste claim is made from mocked tests.

Test matrix: unit tests cover synchronous write before PNG resolution, insecure context, absent clipboard/ClipboardItem, unsupported PNG, denied/throwing API and encoding rejection. Isolated headless UI tests cover no automatic write, explicit click, real PNG signature/dimensions, clipboard/download byte equality, missing APIs, denied write, announced feedback, unchanged score/code and phone overflow. Clipboard write is mocked; downloaded canvas PNGs and phone controls were visually inspected. Lint, types,246 unit tests,nine rendered tests/build and existing settings regressions passed. Native external-app paste remains untested; no foreground use was requested for this patch.
